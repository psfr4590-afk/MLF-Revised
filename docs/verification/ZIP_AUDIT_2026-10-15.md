# ZIP Audit and Corrections — 2026-10-15

## Scope

Audited the supplied `ML-Framework-main.zip` as an extraction source. The archive is preserved unchanged. This working copy is a corrected candidate, not a release-certified build.

## Corrections applied

1. **Tokenizer alphabet:** the ByteLevel BPE trainer now explicitly seeds `BpeTrainer.initial_alphabet` with the complete `ByteLevel.alphabet()` (256 symbols), sorts the symbols deterministically for fingerprinting, and records the alphabet size, SHA-256 fingerprint, and codepoints in tokenizer provenance. Training fails early when configured vocabulary size cannot hold the full alphabet plus the configured unique special tokens.
2. **Tokenizer reversibility:** removed NFKC normalization from the ByteLevel tokenizer path. Applying compatibility normalization before byte-level tokenization can alter mapped symbols and undermine reversible byte coverage. If text normalization is desired, it must be an explicit, separately specified corpus policy rather than silently changing tokenizer byte semantics.
3. **Tokenizer load diagnostics:** missing `tokenizer.json` is reported before a missing optional `tokenizers` runtime dependency.
4. **Deduplication dependency handling:** optional `sentence-transformers` and `faiss` symbols are set to `None` when unavailable. FAISS index construction checks the actual imported module, and the streaming embedding path uses exact brute-force cosine search if an index cannot be built.
5. **Manifest evidence:** tokenizer artifact manifest records the alphabet size and fingerprint alongside vocabulary size.

## Findings against requested behavior

- **Full alphabet and fingerprint:** corrected in source. The runtime environment used for this audit does not have the Hugging Face `tokenizers` package installed, so the actual tokenizer training/round-trip test is skipped here. It still needs to pass on the target Windows environment before this is considered verified.
- **GPU/CPU offloading:** NOT IMPLEMENTED as true layer/tensor offloading. The current trainer selects a single device (`cuda` when available, otherwise `cpu`) and moves the entire model to that device. AMP is enabled on CUDA. That is device selection, not CPU/GPU offloading. Do not claim offloading works from this source revision.
- **Streaming:** crawler ingestion and corpus JSONL processing are incremental; shard writing uses memory-mapped output; semantic dedup consumes the input iterator in batches. However, global dedup retains all surviving representatives and their vectors in memory to compare later documents and permit a higher-weight duplicate to replace an earlier representative. Input streaming is not constant-memory global deduplication.
- **Deduplication correctness:** global representative/weight replacement and streaming regression tests pass in the available environment. The semantic embedding path still depends on a local sentence-transformer model for embedding quality. The token-gram fallback is deterministic but is not equivalent in quality to embedding-based semantic deduplication.
- **Avoiding repeated artifact builds:** stage reuse is gated by resume mode plus artifact integrity and exact provenance matching. Changed inputs/configuration invalidate reuse and trigger rebuilds. Training is different: it resumes from a compatible checkpoint when configured; it is not a general artifact cache that skips training merely because a prior checkpoint exists. A fresh completed run receives a new run identity. These are intentional safety distinctions, not a guarantee that every repeated command avoids work.
- **Actual GGUF:** not verified by this audit. A non-empty file or successful conversion is not sufficient; it must load and generate with the user's local `llama.cpp` binary.

## Release blockers

1. Add and test true CPU/GPU offloading only after specifying target hardware, VRAM/RAM budget, layer placement policy, and throughput expectations. Current implementation must not be represented as offloading.
2. Run tokenizer training and exhaustive byte round-trip tests with the supported `tokenizers` version on Windows.
3. Run full suite in the supported dependency environment.
4. Validate actual checkpoint recovery against the user's checkpoint and intended context length.
5. Export GGUF and prove load + generation with the local `llama.cpp` build.

## Resource-efficient workflow

Use resume/reuse with exact provenance for preprocessing stages; do not weaken identity checks just to skip work. Avoid rebuilding the dataset/tokenizer/shards when their inputs and configuration are unchanged. Training checkpoints are resumable state, while final export is a distinct artifact that should be regenerated when the checkpoint or export settings change.
