# Phase 9: Export, inference, and deployment\n\nPhase 9 proves that the exact release-candidate checkpoint can leave the training environment and execute through independent inference runtimes.\n\n## Export chain\n\ncheckpoint → Hugging Face-compatible checkpoint → F16 GGUF → Q4_K_M / Q5_K_M / Q8_0\n\nRun the complete RC export set:\n\n```bash\npython scripts/export_gguf.py \\n  --output-dir output \\n  --llamacpp-dir third_party/llama.cpp \\n  --quant ALL \\n  --checkpoint output/checkpoints/ckpt_final.pt\n```\n\nThe exporter validates checkpoint integrity and training provenance before writing the Hugging Face-compatible intermediate at output/export/hf/. It then uses the pinned llama.cpp converter to create F16 GGUF and llama-quantize to create each requested quantization.\n\n## Per-export evidence\n\nEach requested quantization receives output/gguf/export_manifest_<QUANT>.json.\n\nEvery per-export manifest records:\n- exact checkpoint path and SHA-256\n- checkpoint step\n- complete model configuration\n- export configuration\n- exporter version\n- pinned llama.cpp converter version\n- UTC timestamp\n- Hugging Face intermediate files and hashes\n- final GGUF path, size, and SHA-256\n- Modelfile path and SHA-256\n- upstream training lineage and parent artifact IDs\n\noutput/gguf/export_manifest.json is the aggregate release manifest and lists every generated GGUF.\n\n## llama.cpp verification\n\nVerify an exported artifact directly:\n\n```bash\npython scripts/verify_gguf.py \\n  --model output/gguf/model-q4_k_m.gguf \\n  --llamacpp-dir third_party/llama.cpp \\n  --context-length <seq_len> \\n  --bos-token-id <bos_id> \\n  --eos-token-id <eos_id> \\n  --pad-token-id <pad_id>\n```\n\nThe verifier checks GGUF metadata, architecture, embedded context length, tokenizer metadata, special-token IDs, tensor integrity, model loading, and actual generation.\n\n## Ollama verification\n\nThe exporter creates a Modelfile for every quantization. Verify the complete Ollama path: GGUF → Modelfile → ollama create → ollama load → generation.\n\n```bash\npython scripts/verify_ollama.py \\n  --model output/gguf/model-q4_k_m.gguf \\n  --modelfile output/gguf/Modelfile-Q4_K_M \\n  --model-name model-lab-rc-q4\n```\n\nOllama is intentionally an external deployment dependency, not a Python package dependency. The verifier fails closed if the executable, Modelfile, model creation, model loading, or generation step fails.\n\n## Native release gate\n\nThe native release verifier now exports all four required formats and validates each GGUF with llama.cpp:\n\n```bash\npython scripts/verify_release.py --bootstrap-native\n```\n\nFor the complete Ollama deployment gate on a host with Ollama installed:\n\n```bash\npython scripts/verify_release.py --bootstrap-native --verify-ollama\n```\n\nThe second command verifies every exported quantization through Ollama as well as llama.cpp.\n\n## Exit gate\n\nPhase 9 is complete for an RC only when the exact approved checkpoint passes checkpoint integrity and provenance validation, produces the Hugging Face-compatible intermediate, produces F16/Q4_K_M/Q5_K_M/Q8_0 artifacts, records per-artifact hashes/configuration/exporter version/timestamp/lineage, loads and generates through llama.cpp, passes context/tokenizer/special-token deployment checks, and passes Ollama create/load/generation when the Ollama deployment gate is required.\n\nExport success is not model-quality evidence. Phase 8 owns model evaluation; Phase 9 proves transport and execution outside the training runtime.\n
